Monitoreo móvil de KPIs transaccionales y detección temprana de anomalías

FinPulse Mobile permite a analistas e Incident Managers vigilar tasa de aprobación, latencia y volumen de cuatro canales de pago (PSE, QR Bancolombia, tarjeta débito y transferencias) desde el celular mediante un servicio FastAPI con reglas SLA y Z-Score.

Autores: Juan José Raigoza Calderón · Jorge Mario Vélez Osorio

01 · Situación problema y pregunta de investigación

Cuando un canal de pago se degrada, el analista suele enterarse tarde

Los canales electrónicos operan bajo SLA estrictos (referencia usada: aprobación superior al 95 %). El problema central es el monitoreo móvil ineficiente que eleva el tiempo de recuperación (MTTR).

01

Tableros pensados para escritorio

Las herramientas tradicionales de BI resultan pesadas e incómodas al consultarse desde un teléfono.

02

Monitoreo reactivo

Hay que abrir manualmente el tablero y refrescar la vista para notar la degradación de un canal.

03

Sin alerta estadística

Sin umbrales combinados con análisis histórico, la caída se descubre cuando los clientes ya reclaman.

Transparencia metodológica: las cifras de contexto como «tableros de 8 s en 4G» o «detección de 15–30 min» son supuestos del enunciado del problema; este proyecto no las midió. Las mediciones propias se detallan en el benchmark del servicio local.

Pregunta problema y objetivos

¿Cómo puede una aplicación móvil conectada a un servicio en la nube detectar y notificar una caída transaccional en segundos, sin que el analista tenga que abrir un tablero?

Objetivos específicos

  1. 1. Modelar un flujo sintético de 4 canales con agregación por minuto e inyección controlada de fallos.
  2. 2. Implementar un motor híbrido combinando reglas de negocio SLA y Z-Score estadístico global.
  3. 3. Exponer los KPIs mediante una API REST en FastAPI documentada con OpenAPI/Swagger.
  4. 4. Presentar los indicadores en un cliente móvil con gráfico de tendencia y notificación de anomalías.
  5. 5. Siguiente fase: desplegar en Google Cloud Run y conectar la app Android al API con push real (FCM).

    05 · Prerrequisitos técnicos
    
            
    
              Qué se requiere para implementar y ejecutar FinPulse Mobile
            
    
            
    
              
    
                
    Backend + PWA (Local)
    
                
      
                  
    • Python 3.10 o superior y gestor de entornos venv.
      • 
                  
    • Dependencias fijadas en backend/requirements.txt (FastAPI, Uvicorn).
      • 
                  
    • Navegador moderno (Chrome, Edge o Firefox) con acceso a Internet para cargar Chart.js desde CDN jsDelivr.
      • 
                  
    • Para reproducir métricas: python scripts/benchmark.py con el API activo en puerto 8000.
      • 
                
    
              
    
              
    
                
    App Android Nativa (Opcional)
    
                
      
                  
    • Android Studio con sincronización Gradle y JDK 17.
      • 
                  
    • Emulador (p. ej. Pixel 7, API 34) o dispositivo físico con Android 8.0+ (API 26+).
      • 
                  
    • Aceptar permiso de notificaciones en tiempo de ejecución (Android 13+).
      • 
                  
    • Nota: la versión actual simula KPIs localmente en el dispositivo.
      • 
                
    
              
    
              
    
                
    Despliegue en Nube (Fase siguiente)
    
                
      
                  
    • Docker + Google Cloud Run para exponer el servicio FastAPI con URL pública HTTPS.
      • 
                  
    • Firebase (FCM + Firestore) o Redis para push real y estado compartido entre réplicas.
      • 
                  
    • Seguridad pendiente: autenticación JWT y política CORS restrictiva.
      • 
                  
    • Cuentas en Google Play Console ($25 único) y Apple Developer ($99/año) si se publica en tiendas.
      • 
                
    
              
    
            
    
          
    

          
    
            
    
              
    Limitaciones declaradas
    
              
      
                
    • Datos sintéticos: las anomalías son inyectadas, no observadas en producción.
      • 
                
    • Sin despliegue público ni autenticación JWT todavía.
      • 
                
    • La app Android aún simula datos locales y no consume el API.
      • 
                
    • Sin pruebas automatizadas en backend ni medición en red móvil 4G/5G ni encuesta SUS.
      •
